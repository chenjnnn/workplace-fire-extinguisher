# 打飞坏领导 · 设计与机制文档

> 消除类小游戏：三连清场，清除的对象是**虚构的**诈骗犯、毒贩、贪官、恶霸、保护伞。
> 网页版已完成，小程序版复用同一套内核。

---

## 一、合规边界（先看这一节）

这个题材最大的风险不是技术，是**内容和法律**。已落地的约束：

| 做 | 不做 |
|---|---|
| 五种**虚构卡通角色**（代号化，无真人指认） | 任何真实人物姓名、职务、肖像 |
| 捏人系统用**固定枚举**组合（性别/发型/表情/行头/道具） | 上传照片、自由文字输入、填写真实姓名 |
| 消除反馈是「逮捕/清场」，无血腥表现 | 暴力、血腥、私刑实感 |
| 首页与结算页都有**虚构声明** | — |

代码层面的保证（不是靠自觉）：

- `packages/game-core/src/types.ts` 的 `AvatarConfig` **只有枚举字段**，没有任何 `string` 自由文本
- `sanitizeAvatar()` 会把任何不在白名单里的值打回默认值，篡改存档也没用
- `share.ts` 的 `DISCLAIMER` 常量被结算页和分享海报强制引用

> 如果将来要做「拍照生成卡通形象」，必须是独立功能 + 明确标注 + 服务端审核，
> 不能塞进现有捏人页。

## 二、主题：职场坏领导

### 为什么换主题

第一版是「诈骗犯/毒贩/贪官」，问题很明显：**离玩家太远**。
你不会在电梯里遇到毒贩，但你会每天遇到让你加班的人。

第二版换成 **5 种职场坏领导**，每一种对应一种具体的职场伤害：

| 类型 | 形象 | 口头禅 | 机制呼应 |
|---|---|---|---|
| 画饼王 | 地中海 + 金丝眼镜 + 假笑 | 「年轻人要看长远」 | 基础型 |
| 甩锅侠 | 锅盖头 + 大小眼 + 歪嘴 | 「这个我不是交代过你吗」 | 消除后甩锅污染相邻格 |
| 抢功精 | 大背头 + 墨镜 + 大笑 | 「这个项目是我带着做的」 | 要清两次才倒 |
| 加班魔 | 爆炸头 + 血丝眼 + 龇牙 | 「反正你也没什么吧」 | 被打掉时反咬一口 |
| 形式怪 | 中分 + 圆框眼镜 + 面瘫 | 「先做个周报同步一下」 | 十字爆裂，掀掉他那堆表格 |

**机制和口头禅是对应的**——不是随便贴的标签。甩锅侠真的会甩锅（污染格子），
抢功精真的要抢两次（第一次只丢 PPT），这是这个设计成立的关键。

### 受害者 = 打工人

救援卡上的人不再是「张阿姨」，而是：
- 小林：「入职两年，工资没涨，饼吃了三张」
- 小美：「已经连上 12 天班，工位有张折叠床」
- 陈工：「方案是他写的，汇报是他领导去的」

### 话术系统 —— 这个游戏的灵魂

消除是动作，**话术才是情绪出口**。

**失败时**：弹一句领导的 PUA（从 12 条里按 boss 类型抽）

```
画饼王 说：
「年轻人不要总盯着工资，要看重成长。」
潜台词：成长是你的，钱是我的。
```

设计意图：让失败**不那么挫败**，而是变成「又听到这句了」的会心一笑。
输的时候看到这个，玩家会想「我就是要打赢你」。

**通关时**：触发「话术对决」，领导挑衅 → 你从 3 个应对里选一个

```
画饼王说：「这个方向我早就想过了，只是还没来得及说。」

A. 那您真是高瞻远瞩，连我做的都能提前想到。   （讨好 +0）
B. 想过了但没说，等于没想。                 （反杀 +80，标「最佳」）
C. 嗯，我记下了。                          （中性 +20）

→ 选 B：他沉默了三秒，说「你这个态度要改改」——但你知道他答不上来。
```

三个选项分别对应「忍」「怼」「和稀泥」，**反杀选项要有真的能说出口的锋利感**。

## 二·四、核心交互：扇巴掌

游戏叫「打飞坏领导」，所以消除的形式不是「消失」，是**被扇飞**。

### 动画时序（340ms）

```
0 – 35%   一只手从右侧扫进来，手掌张开
35%       到位 —— 啪！冲击环 + 6 道速度线 + 3 颗星星
35 – 78%  手掌停留，被扇中的领导旋转着飞出去（带 2 层拖影）
78 – 100% 手和牌一起淡出
```

配合一声「啪」（短促高频噪声 + 低频撞击），这是整个游戏最直接的爽点。

### 踩过的两个坑

**坑 1：每张牌各画一只手**
一次消除 3 张牌 → 3 只手同时出现，像群魔乱舞。

**坑 2：一组只画一只手，但位置取「消除区域中心」**
如果消除发生在第 0 行，手的中心 y ≈ 26px，直接被画到画布外，看不见。

**最终做法**：一组一只手，位置取中心但**钳制到棋盘安全区**（`cell*0.7 ~ height - cell*0.7`），
尺寸放大到 `cell * 1.15`，存活 340ms。

### 掉落式的牌怎么飞

模型里被消除的牌已经删了，但动画还要它在画面上飞 0.34 秒。
所以单独维护 `flyingTiles`：记录起飞点、方向、开始时间，渲染时按进度算位移和旋转。

方向用格子坐标做伪随机（`row*73 + col*131`），同一局里飞散方向杂乱但**可复现**。

## 二·四b、视觉系统（第五轮：去 AI 味）

用户的原话：「字体 AI 味太浓，页面设计请参考手机竖屏休闲游戏 UI，
卡通扁平化风格，纯色块，轻微圆角，无厚阴影无描边，字体用圆润粗圆体。」

### 字体

| | 之前 | 现在 |
|---|---|---|
| 标题 | 站酷快乐体 | **Zen Maru Gothic**（真圆体）+ 系统圆体兜底 |
| 字重 | 400 | **800** |
| 正文 | 系统黑体 | 系统黑体（保持干净柔和） |

**为什么站酷快乐体会「AI 味重」**：它是手写装饰体，笔画粗细不均、带手绘抖动。
这种字体适合海报标题，不适合游戏 UI —— 游戏 UI 要「粗、圆、无装饰、机械感稳定」。

字体栈（按平台优先级，网络字体失败也不难看）：
```
Zen Maru Gothic → Yuanti SC(macOS 圆体) → YouYuan(Windows 幼圆) → PingFang SC
```

### 视觉规格

| 项目 | 规格 |
|---|---|
| 背景 | 纯色 `#fff8ec`（不用渐变） |
| 卡片 | 纯白，无边框 |
| 圆角 | `rounded-xl`（12px），按钮才用全圆 |
| 阴影 | 全部去掉（原来 `shadow-lg` / `shadow-2xl` 全删） |
| 描边 | 去掉 `border-2` 强调边框 |
| 主色 | `#ff6b4a` 珊瑚橙（纯色，不用渐变） |
| 强调块 | 纯色块（淡黄 `#fff0c2`），不用边框 |

**「无厚阴影」是最关键的一条**：休闲游戏的卡片是「贴」在背景上的，
不是「浮」在上面的。厚阴影会让画面显得脏、显得像 2010 年的拟物 UI。

## 二·四c、暂停菜单（第七轮）

用户的要求：「在游戏画面右上角加一个"☰ 菜单键"，点击后游戏立即暂停并弹出半透明遮罩和暂停面板，
面板包含"继续游戏""重新开始""返回主菜单"三个按钮；暂停期间所有游戏逻辑、计时和动画冻结，
点击遮罩外或按 Esc 也可继续。」

实现要点：

| 要求 | 做法 |
|---|---|
| 按钮在右上角 | 顶栏最右侧，带「☰ 菜单」文字（之前只有图标，不好找） |
| 立即暂停 | `engine.pause()` 取消 `requestAnimationFrame` |
| 所有逻辑冻结 | 渲染循环停了，`advanceRescue`（救援倒计时）也跟着停 |
| 半透明遮罩 | `bg-[#2e2a24]/55` + `backdrop-blur` |
| 三个按钮 | 继续游戏 / 重新开始 / 返回主菜单 |
| 点遮罩继续 | 遮罩 `onClick` 关面板，面板 `stopPropagation` |
| Esc 继续 | `keydown` 监听 Escape |

**一个坑**：加 Esc 的 `useEffect` 一开始放在了 early return 之后，
React 报 `Rendered more hooks than during the previous render`，整页崩。
这个项目里已经踩过两次同样的坑（菜单暂停、囚车头像），**所有 hooks 必须在 early return 之前**。

## 二·四d、囚车（替代进度条）

用户的原话：「上面的收网和进度条的关系很不明确，可以把进度条换成一个囚车或者监狱，
然后每消掉一次，就放上去一个对应的头像，然后满多少个说明过关。」

### 为什么囚车比进度条好

进度条是「数字的图形化」，玩家要看两次（先看条、再看数字）才明白进度。
囚车是「把坏人关进去」—— **一个动作对应一个结果**，看一眼就知道还差几个。

### 实现

- 车厢用深灰蓝 `#3d4655`，牢房用更暗的 `#2b323d`，铁栏用半透明白 —— 对比强，一眼是笼子
- 12 个牢房位，每格代表 `total / 12` 的进度
  （目标动辄 30-80，不可能真放 80 个头像；12 格是「变化够勤」和「放得下」的平衡点）
- 关进去的放对应类型的头像，空的画三根竖栏
- 顶部红蓝警灯条，底部两个轮子

### 收网按钮

原来「怒值满了 HUD 里的卡片变成收网按钮」，问题是**它的位置和进度条毫无关系**，
玩家不知道这两个数字在说什么。

现在改成囚车右侧的**警笛按钮**：
- 可用：橙底白字 + 🚨
- 不可用：灰底 + 「未满」
- 右上角小角标显示本关还能用几次
- HUD 里的怒值卡片降级成纯显示（只显示百分比，不可点）

这样「打坏人 → 关进囚车 → 怒值满 → 收网清一波」形成一条视觉动线。

## 二·四e、完整的页面状态机（第八轮）

用户的原话：「你要做成一个成熟的游戏，有返回退出键等等的，现在通关之后我就什么都做不了了。
把游戏补成完整可导航的状态机，不要改核心玩法。」

### 那次的「卡死」根因

游戏页给 `body` 加了 `overflow: hidden`（防止拖拽棋盘时整页跟着滚）。
结算页内容比屏幕高，按钮被顶到屏幕外 —— **而页面又不能滚动，玩家永远看不到按钮**。

修法两层：
1. 结算时移除 `game-locked`，让页面能滚
2. 更根本的：把结算页改成「内容可滚动 + 底栏固定」

```
┌──────────────────────┐
│ 清场完成              │  ← 可滚动区
│ 话术对决              │
│ ⭐⭐⭐                │
│ 得分 9,200           │
│ 清理总数 / 最高连锁    │
├──────────────────────┤
│ [ 下一关 · 第 2 关 ]  │  ← 固定底栏，永远可见
│ [重玩][分享][选关]    │
│      返回主菜单       │
└──────────────────────┘
```

### 每个状态都要有出口

| 状态 | 可点的地方 |
|---|---|
| 主菜单 | 开始游戏 / 玩法说明 / 关卡选择 / 捏领导 / 音效 |
| 玩法说明 | 上一步 / 下一步 / 跳过 / 开始游戏 |
| 开场动画 | 开打 / 回去选关（点任意处跳过打字） |
| 游戏中 | ☰ 菜单 |
| 暂停 | 继续游戏 / 重新开始（二次确认）/ 返回主菜单（二次确认）|
| 失败页 | 再来一次 / 重玩本关 / 分享 / 选关 / 返回主菜单 |
| 通关页 | **下一关**（主按钮）/ 重玩本关 / 分享 / 选关 / 返回主菜单 |

**二次确认**：重开和返回主菜单都会先问一句 —— 因为这两个操作会清空本局进度，
误触代价很高（尤其暂停面板上「继续游戏」和「重新开始」挨得很近）。

确认文案会说明「清空什么、保留什么」：
> 返回主菜单？本局分数和进度会清空，最高分和已解锁关卡会保留。

### 玩法说明

首次进游戏自动弹，3 页卡片：目标 / 操作 / 失败条件。
每页有图标 + 一句话 + 小示意图，底部「上一步 / 下一步 / 跳过」。
看完或跳过后写 `localStorage['villain-clear:tutorial-seen']`，之后不再自动弹；
主菜单的「玩法说明」按钮可以随时重看（同一个组件，只是按钮文案变成「知道了」）。

## 二·四f、通关庆祝动画

用户的要求：「一群小头像在舞台里乱窜逃跑，一只卡通巴掌追着最近的头像挥过去，
拍中后头像旋转飞出、冒出星星和"啪"字，巴掌停顿回弹，然后继续追下一个头像，循环播放。」

实现：**纯 CSS 关键帧，不碰 canvas**。

| 元素 | 动画 |
|---|---|
| 逃跑的头像 ×5 | `flee`：左右上下乱窜 + 旋转，每个不同时长（3.1-4.1s）和延迟 |
| 巴掌 | `chaseMove`：从右侧冲进来 → 挥下（放大 1.15）→ 停顿回弹 → 退回 |
| 「啪！」 | `wordPop`：跟着挥手节奏闪，45% 时放大到 1.25，72% 后淡出 |
| 卡片 | `bg-white/92` 半透明，让背景动画透出来 |

**为什么不用 canvas**：这个动画和玩法完全无关，
用 CSS 就不会和渲染循环抢时间，也不会因为暂停/恢复出问题。
另外加了 `prefers-reduced-motion` 的降级（系统开了「减少动态效果」就不动）。

**踩的坑**：第一版卡片是纯白 `bg-white`，动画完全被盖住，DOM 里有元素但看不见。
改成半透明后还要注意别用 `backdrop-blur` —— 它会把背景动画糊成一团色块。

## 二·五、场景与任务

用户要求「场景设计的细致一些，在什么场景内，要完成什么任务，然后开始游戏」。

所以每个关卡有两层包装：

1. **数据层**：`LevelConfig.scene = { name, desc, mission }`
2. **界面层**：进关卡先弹「任务卡」，点「开打」才进棋盘

任务卡长这样：

```
第 2 关 · 会议室
    周一早会
┌────────────────────────────────┐
│ 周一九点，全组被叫进会议室。说好    │
│ 十分钟的会，投影仪还在连不上，已经  │
│ 过去四十分钟。                     │
└────────────────────────────────┘
┌────────────────────────────────┐
│ 你的任务                        │
│ 趁他还在讲「上周的复盘」，把画饼王  │
│ 从会上扇出去。                    │
└────────────────────────────────┘
      34 步 · 画饼王 / 甩锅侠
      ┌──────────────────┐
      │      开 打        │
      └──────────────────┘
```

**为什么 desc 要写得具体**（时间、地点、细节）：
抽象的任务（「消除 30 个画饼王」）不会让人有代入感，
但「投影仪还在连不上，已经过去四十分钟」会 —— 因为每个人都经历过。

### 开场动画（第六轮：把卡换成动画）

静态卡的问题是「读一段字再点按钮」，没有动机感。改成三幕动画：

```
第一幕  领导从右侧滑入 → 说一句他会在这种场合说的话（打字机，52ms/字）
第二幕  场景描写淡入
第三幕  任务块浮现 → 「开打」按钮弹出
```

台词是每关单独写的，不是通用 PUA。比如：
- 周一早会：「大家简单说一下，每个人五分钟，不要超时。」
- 项目冲刺：「这个需求今天下班前能给我吗？不难吧？」

**为什么台词比场景描写更重要**：描写是在「讲」处境，台词是在「演」处境。
听见这句话的人会立刻想起自己被这么说过。

点击任意处可跳过动画，直接到「开打」。

### 两个坑

**坑 1**：开场卡挡住 canvas，导致 `GameEngine` 的挂载 effect 拿不到元素、引擎没初始化（步数为 0）。
修法：把 `briefed` 加进 effect 依赖，点「开打」后重新初始化。

**坑 2**：场景色块用 `#fff0e6`，和背景 `#fff8ec` 几乎一样，看不出来「有场景」。
修法：饱和度提高一档（`#ffdcc7` 等），并让色块整屏铺满、底部用圆角浅色地面收口。

## 二·五b、问答拿工具（第三轮玩法迭代）

用户的要求：「游戏过程中加问答获得工具或技能，领导说一句话，给几个选项让你选怎么回应让他吃瘪，
答对了就能获得工具。」

### 玩法

```
每消除 20 个 → 领导突然冒出来挑一句 → 3 个回应 → 选对拿工具 → 道具立刻生效

**每局最多弹 3 次**（用户反馈「弹出来太频繁了，都没办法连续玩游戏」）。
最初是每 12 个一次，大关卡一局能弹 5-6 次，严重打断节奏。
```

**为什么这个设计能救「消除很无聊」**：
消除是纯机械动作（凑三个）。而「被领导点名 → 当场怼回去 → 拿到东西」
是一条有情绪回报的链路，它**打断了机械流程**。

### 24 道题的设计规则

每道题**只有一个正确答案**，另外两个是常见但吃亏的回应：
- 一个「认怂」（对不起我调整一下）
- 一个「和稀泥」（我尽量吧）

这样玩家答错的代价不是「扣分」，而是**学到原来这么说才不吃亏**。

题面举例：

| 领导说 | 最佳回应 |
|---|---|
| 「你最近是不是有点不在状态？我看你准点就走了。」 | 「我的工作都按时交付了。准时下班不叫不在状态。」 |
| 「这个方案当初谁定的？现在出问题了吧。」 | 「是您在上上周的会上拍板的，纪要里有。」 |
| 「这次汇报我来讲吧，你讲容易讲不清楚。」 | 「这个方案我做了三周，我讲最清楚。要不我讲，您在旁边补充？」 |
| 「如果公司现在让你降薪 20%，你能接受吗？」 | 「可以接受，那我们先把公司的亏损数据拿出来一起看。」 |

### 11 件工具（要能「制服」领导）

用户的原话：「可以设计一些工具，例如更大的 boss 制服坏领导、纪检部门查到他受贿等
能够制服坏角色的工具，而工具在游戏中对应着清除页面获得积分，或者说清除一行或者一列。」

所以工具不只是「加分」，是**真的改棋盘**：

| 工具 | 效果 |
|---|---|
| 🚪 上级领导突击检查 | **清掉一整行** |
| 🔍 纪检部门进驻 | **清掉一整列** |
| ⚖️ 劳动仲裁开庭 | **清掉一行 + 一列** |
| 📰 媒体曝光 | 随机清掉 8 个 |
| 📄 律师函 | +900 分 |
| 💰 同行工资单 | +700 分 |
| 📇 猎头名片 | +600 分 |
| 🎙️ 录音笔 | +3 步 |
| ☕ 续命咖啡 | +2 步 |
| 🤝 工会代表 | 怒值 +50% |

**「清一行」的实现要点**：
挑「最满的那一行」清掉 —— 视觉上最爽，也最有用。
清完走一遍 `applyGravity` + `refillBoard`，把棋盘补满，
否则玩家会看到棋盘缺一块、后续无法消除。

### 答题后的评价：盖章（第三版，按规格实现）

前两版都失败了，原因值得记下来。

**第一版**：印章用 `scale(2.4) → scale(1)` 放大浮现 —— 像「贴纸浮出来」，不像盖章。
另外 `<style jsx>` 样式块在某次编辑中丢了，章是「突然出现」的。

**第二版**：拆成 `stampFall`（下落）和 `stampSquash`（压扁）两个动画。
`stampSquash` 带 300ms 延迟和 `both` 填充，而 `both` 会在**延迟期就应用 0% 帧的样式** ——
它的 0% 帧是 `translateY(0)`，于是把下落动画整个覆盖掉了。
表现就是：章直接在终点出现，完全看不到下落。
（用 `getComputedStyle` 打出 transform 矩阵才发现的：`translateY` 分量恒为 0。）

**第三版（现在）**：合并成一个 `stampDrop` keyframes，不再有两个动画抢 transform。

具体参数：

| 阶段 | 时间 | 动作 |
|---|---|---|
| 落点阴影 | 0-100ms | 选项中心冒出椭圆阴影，scale 0 → 1 |
| 下落 | 110-410ms | 从落点上方 150px、scale 1.4、rotate -12° 加速砸下（`cubic-bezier(0.45,0,0.95,0.55)`） |
| 落地 | 410ms | scaleY 压到 0.85 再回弹；弹窗容器震 150ms；墨迹向四周扩散淡出 |
| 停留 | 410-1210ms | 章停在选项上 0.8 秒，期间禁止重复提交 |
| 奖励卡 | 1210ms | 弹出星级 / 得分 / 道具名称 / 效果 / 用处 |

**正确 vs 错误的视觉区分**：

| | 章的内容 | 颜色 | 倾斜 | 额外 |
|---|---|---|---|---|
| 正确 | ✓ 正确 | 绿 | -8°（正盖） | — |
| 错误 | ✗ 错误 | 红 | +12°（歪一点） | **正确答案描边高亮**（绿色内阴影） |

「正确答案是第几个」原本故意不给 UI（防泄题），
但答完之后就没关系了 —— `answerQuizOption` 会返回 `correctIndex`。

### 一个必须记住的 CSS 坑

`animation-fill-mode: both` 在**延迟期间**就应用第一帧样式。
两个动画同时改 `transform` 时，带延迟且 `both` 的那个会覆盖另一个。
以后再做「先落下再压扁」这种串行动画，**要么合并成一个 keyframes，要么改用 `forwards`**。

### 「一次性 + 随机 + 不重复」怎么保证### 「一次性 + 随机 + 不重复」怎么保证

用户明确要求：「场景、问答题都不能重复，全部都是一次性的而且是随机的，
每个用户玩到相同的关卡，遇到的场景和问答不一样」。

实现：
1. **一次性**：答过的题 id 进 `usedIds`，抽题前先过滤掉
2. **随机**：用 `Date.now() ^ (totalCleared * 7919)` 做种子洗牌
3. **跨局不重复**：`usedIds` 存 localStorage
4. **池子抽空后重置**：否则老玩家会没题

### 场景随机化

每个关卡现在有 **2 套场景**（默认 + `sceneVariants`），进关时用 `pickScene(level, seed)` 随机选一个。

同一关的两套场景是「同一个处境的不同角度」，不是随便换：
- 第 1 关 A：入职培训室，HR 讲「我们是一家人」
- 第 1 关 B：工位区，老员工低声说「这里说的话，别都信」

### 踩的三个坑

**坑 1：用 `totalCleared % 12 === 0` 判断触发**
一次消除加 3-10 个，会**直接跳过 12、24、36**，结果永远弹不出来。
改成「跨过了几道门槛」：`Math.floor(totalCleared / 12) > quizzesTaken`。

**坑 2：`Date.now()` 写在 render 里**
服务端渲染和客户端 hydration 算出不同的场景，React 报 hydration mismatch 并重建整棵树。
改成在 `useEffect` 里生成种子。

**坑 3：答完题弹窗立刻消失**
`hud.pendingQuiz` 在答题后马上就变 null，而弹窗的显示条件就是它，
所以玩家根本看不到「我选对了吗、拿到了什么」。
修法：弹窗出现时把题目快照到本地 state，直到点「继续打」才释放。

**坑 4：`this.onFinish` 不存在**
回调存在 `this.options.onFinish`，写成 `this.onFinish` 会在触发结算时抛
`TypeError: this.onFinish is not a function`。

## 二·六、掉落式（新玩法实验，未上线）

### 先说说被砍掉的贪吃蛇

第一版做的是「蛇吃牌 → 蛇身凑三个同类就消」。用户反馈：**没意思**。

复盘为什么没意思：
1. **蛇身只是个「待消除的池子」**，和棋盘空间完全脱钩 —— 你吃什么都一样
2. **吃牌不产生连锁**，没有「砰一下清一片」的爽感
3. **感受不到「我的操作改变了局面」** —— 蛇只是路过，棋盘不会因此变化

一句话：它是「带移动的队列管理」，不是「消除」。

### 掉落式：让玩家亲手堆出棋盘

核心变化：**棋盘不再是系统生成的，是你一块一块堆出来的。**

```
一个牌从顶上掉下来 → 你左右移动选列 → 落下 → 检查三连 → 消掉 → 上方砸下来 → 可能连锁
                                                              ↘ 堆到顶部 = 死
```

为什么这个「有意义的操作」：
- 每一个决策都有代价：放这里能消，但会堵住旁边那列
- 消除引发掉落，掉落引发新的三连 —— 有连锁爆炸感
- 你输的时候，看得到自己堆出来的那面墙

### 三个致命 bug（都是实测跑出来的）

**bug 1：一组 3 个牌，永远凑不出横向三连**
初版每次落 `[A, A, B]` 三个牌。横向只有 2 个 A，凑不出 3 连；
纵向要连续三次落到同一列同色，几乎不可能。
结果：**10 步就堆满，得分 0**。

**bug 2：改成「故意制造对子」也不够**
在预填的棋盘里放一些 `AA`，想让玩家补第三个 A。
但整组横向移动，玩家没法精确对齐，**15 步只消 3 个**。

**bug 3（最终解法）：单牌掉落**
一次只落 **1 个**牌，玩家可以精确控制它落在哪一列。
配合预填里的对子，玩家能清晰地「看到 AA → 补 A → 三连」。

改完之后：**20 步完成 15 个目标，得分 750**。

### 留下的设计约束

| 约束 | 原因 |
|---|---|
| 一次只落 1 个 | 整组移动无法精确对齐，凑不出三连 |
| 预填必须制造对子 | 对子是玩家唯一的「目标提示」，没有对子就不知道该补什么 |
| 棋盘 7×12 | 9 行太矮，堆叠速度超过思考速度 |
| 目标 15 | 20 个在实战里几乎打不完 |

## 三、核心玩法

### 2.1 基础循环

```
拖动/点选相邻两格 → 交换 → 三个同类型连成一线 → 消除 → 掉落 → 连锁
```

- 7×7 棋盘（后期关卡 8×7、8×8）
- 开局保证「没有现成三连」，且「一定存在可行步」
- 无可行步时自动重排（保留所有格子，只打乱位置）
- 连锁倍数封顶 **2.6 倍**（原设计 4 倍，实测会让分数爆炸，星级失去意义）

### 2.2 五种坏人（机制各不相同）

| 角色 | 颜色 | 「怒」值 | 机制 |
|---|---|---|---|
| 诈骗犯 | 青 | 1 | 基础型，消除即倒 |
| 毒贩 | 荧光绿 | 2 | 消除后**污染相邻格**（毒雾格要再消一次） |
| 贪官 | 金 | 2 | **两条命**，第一次只掉钱包 |
| 恶霸 | 红 | 1 | 被打掉时**反击扣分**（不扣步数） |
| 保护伞 | 紫 | 3 | **十字爆裂**，打掉时清周围 8 格 |

这些机制是「消消乐」和「换皮消消乐」的分界线：每种角色逼迫玩家用不同策略，
而不只是换个颜色。

### 2.3 收网行动

怒值攒满后可以释放，**清掉全场最多的一类坏人**。

为什么不是「清全盘」：
- 清全盘太强，玩家会一直攒着不放，节奏就断了
- 清一类需要判断「哪类最多/最急」，才有决策乐趣

### 2.4 连击文案（最廉价的爽点）

| 连锁层数 | 文案 |
|---|---|
| 2 | 一窝端 |
| 3 | 连锅端 |
| 4 | 跨省追捕 |
| 5 | 天网恢恢 |
| 6+ | 法网难逃 / 无处可逃 |

### 2.5 视觉：扁平色块风（第三轮迭代）

用户给的参考图是「极简扁平色块」风格，对照重画：

| 元素 | 做法 |
|---|---|
| 底 | 低饱和纯色圆（深蓝/绿/金/红/紫） |
| 脸 | 大圆 + 浅肤色，占满棋子 |
| 五官 | 粗黑线条，极简（最多 6 个元素） |
| 西装 | 深一档的纯色肩膀 + 白衬衫 V 领 + 领带 |
| 特征 | 五种完全不同的发型 + 配饰 |

**明确不做**：渐变、霓虹发光、厚涂、描边阴影。这些是「土」的来源。

五种脸的区别：
- 画饼王：大背头（带高光）+ 墨镜 + 平嘴（不屑）
- 甩锅侠：偏分 + 挑眉 + 张嘴假笑
- 抢功精：寸头 + 怒眉 + 龇牙 + 头顶金币
- 加班魔：稀发 + 怒眉 + 龇牙 + 头顶青筋
- 形式怪：中分 + 半睁眼 + 托腮

### 2.5b 字体

标题用 **站酷快乐体**（ZCOOL KuaiLe，Google Fonts 开源），圆润卡通；
正文用系统字体栈。标题字体统一走 `.font-display` 类。

### 2.5c 首页（第四轮迭代）

按参考图重排：大标题 → 副标题 → 5 头像横排 + 短标签 → 「你的专属领导」DIY 卡片
→ 超大主按钮 → 新玩法入口 → 两个小按钮 → 今日领导语录 → 底部小字。

**游戏页的目标条合并成了一个大进度条**（原来是「甩锅侠 0/22 | 画饼王 0/18」两排，
玩家看不懂在追什么）。现在只有一行「距离通关 35/60」。

### 2.5e 两个「分不清」的角色（第五轮）

用户反馈：「图片里的这两个太像了，玩游戏的时候很难分辨」。

确实：甩锅侠（绿）和形式怪（紫）之前都是「圆脸 + 深色头发 + 微笑」，
缩到 40px 在棋盘上几乎一样。修法是**给他们各自一个强符号**：

| 角色 | 符号 | 怎么画 |
|---|---|---|
| 形式怪（紫） | **假笑面具** | 上半张脸盖一张米白色面具，面具上有弯笑眼和小圆嘴；面具下露出的真实嘴巴是一条平线。一眼看到「两张嘴」就知道是假的 |
| 甩锅侠（绿） | **Zzz + 困倦眼** | 头顶三个大小递减的 Z；上眼皮压下来只露下半；嘴是向下弯的短弧 |

**教训**：角色辨识度不能靠「表情的细微差别」，要靠**一眼可辨的形状符号**。
缩到 40px 时，只有大形状（面具轮廓、Z 字形）还看得出来。

### 2.5d 首页

对照参考图重做：大标题 → 副标题 → 5 个头像横排 + 短标签 → 超大橙红按钮
→ 两个小按钮（玩法说明 / 音效）→ 今日领导语录 → 底部小字。

**头像提前露出来**是刻意的：让玩家进棋盘前先认一遍这几个脸，不然第一次见会懵。

### 2.6 救援场景（第一轮迭代新增）

棋盘上方会出现 1-2 个「正在被侵害的人」，每个带倒计时：

```
张阿姨  18s
正被"公检法"电话远程控制，准备转账
[诈骗犯] ████████░░░░░░  12/20   ← 需要清除的坏人类型与数量
         ██░░░░░░░░░░░░          ← 危险条（倒计时）
```

**规则**
- 消除对应类型的坏人 → 进度推进，同时**危险值回退 12%/个**（约 1.8 秒缓冲）
- 危险值涨满 → 救援失败
- 救援失败 **不结束游戏**，只砍星级上限（丢 1 人最多 2 星，丢 2 人只能 1 星）

**为什么不做成「倒计时归零就 game over」**
10 秒内没完成就判负，玩家只会觉得游戏在跟自己作对。我们要的是压力，不是挫败。
现在的设计：压力来自「你不理他，他就没了」，而不是「你操作慢了就结束」。

**为什么只在棋盘可操作时走表**
播放消除动画时暂停倒计时。否则一次长连锁会吃掉 3-5 秒，
玩家会觉得「看动画被扣血」，这是纯粹的恶心设计。

### 2.7 两种模式（第一轮迭代新增）

| | 普通模式 | 解恨模式 |
|---|---|---|
| 连锁上限 | 2.6 倍 | 4 倍 |
| 怒值积累 | 标准 | 只需 55% |
| 收网次数 | 2 次 | 不限 |
| 救援计时 | 标准 | 慢 55% |
| 救援失败 | 砍星级 | 不砍星级 |
| 定位 | 有压力，才够劲 | 今天不生气，只想痛快 |

模式在关卡选择页切换，用 `?mode=catharsis` 传递。
**规则完全一致，只是让玩家赢**——解恨模式不是简单模式，是情绪模式。

### 2.8 棋子的视觉变体（第一轮 + 第二轮迭代）

第三轮把棋子从「彩色球 + 小眼睛」改成了**「一张卡通脸」**，
因为用户的原话是「非常土，设计不好看，用脸比较好」。

现在的画法：
- 脸占满整个棋子（不再是球上贴两个小点）
- 五种脸靠**发型 + 五官 + 表情 + 配饰**四重区分，黑白也能认出
- 发型：地中海 / 锅盖头 / 大背头 / 爆炸头 / 中分
- 眼睛：金丝眼镜 / 大小眼 / 墨镜 / 血丝眼 / 圆框眼镜
- 嘴：假笑露牙 / 歪嘴 / 张嘴大笑 / 龇牙 / 一字嘴
- 身体：西装领 + 领带，做出「半身照」的感觉

第二轮把整体视觉从「暗色霓虹」改成了「鲜亮糖果色」：
- 背景：奶油白 `#fdf6ec`，不再是深夜黑
- 棋子：圆润的彩色球（径向渐变 + 白色内描边 + 顶部高光），像糖果
- 表情：大眼白 + 瞳孔 + 高光 + 腮红，**每个类型表情不同**（诈骗犯歪嘴笑、恶霸咬牙怒眉、贪官张嘴大笑）
- 道具：右下角白色圆形徽章，里面用主色画标志物

为什么把方形卡改成圆形球：
小尺寸下方块之间的颜色对比会被边框和阴影削弱，
而圆形纯色块的视觉重量更集中，**一眼分得清颜色，三消才玩得下去**。

去掉文字后，识别靠「颜色 + 表情 + 道具徽章」三重。

每种坏人 **3 个变体**，但只换道具：

| 类型 | 变体 1 | 变体 2 | 变体 3 |
|---|---|---|---|
| 诈骗犯 | 电话 | 短信信封 | 二维码 |
| 毒贩 | 药丸 | 注射器 | 粉末袋 |
| 贪官 | 钱袋 | 金条 | 酒瓶 |
| 恶霸 | 拳头 | 棒球棍 | 扳手 |
| 保护伞 | 雨伞 | 墨镜 | 公文包 |

**关键约束：变体只改道具，不改主色和头部轮廓。**
三消的可玩性完全建立在「一眼能分辨类型」上。如果诈骗犯的三种形象颜色不同、
轮廓不同，玩家就会认错，游戏立刻变得不可玩。
这个约束在类型定义里写死了：`variant` 字段**不参与匹配**（`match.ts` 只看 `type`）。

### 2.9 捏人系统

10 个维度、上百万种组合，但全部是**固定枚举**：

性别气质 / 脸型 / 发型(7) / 发色(6) / 眉毛(4) / 表情(5) / 行头(4) / 衣服颜色(6) / 随身道具(7) / 肤色(5)

内置 4 个预设（老派处长 / 话痨主管 / 暴躁老板 / 神秘顾问）。

捏出的形象会：
- 出现在首页立绘、游戏顶栏、结算页

### 3.1 为什么自研渲染，不用 Phaser/Cocos

| 考虑 | 结论 |
|---|---|
| 复杂度在哪 | 消除游戏的复杂度在**逻辑和手感**，不在 3D 渲染 |
| 包体积 | 零引擎 + 零图片素材，小程序 4MB 首包限制毫无压力 |
| 捏人 | 必须程序化绘制，不可能预生成立绘素材 |
| 移植 | Canvas 2D API 在微信小游戏里几乎一致，只需换渲染层 |

### 3.2 内核与渲染的分工

```
game-core（纯函数）          engine.ts（Canvas）
────────────────────         ─────────────────────
能不能消？           →       不关心
得多少分？           →       不关心
格子掉到哪一行？     →       写进 tile.dropFromRow
                             → 按 dropFromRow 插值出掉落动画
```

关键设计：**「消除/掉落」本质上只是格子位置的变化**，
所以只需要一套「位置插值」动画逻辑，不需要给每种动画写代码。

### 3.3 确定性随机

所有随机都走 `createRng(seed)`，好处：
1. 每日挑战可以全服同一副棋盘（`seedFromDate`）
2. 出 bug 能凭种子 100% 复现
3. 单测可复现

## 四、关卡平衡（实测数据）

用「每步都走最优提示」的贪心模拟，每关跑 12 局：

| 关卡 | 胜率 | 用步中位 | 三星率 |
|---|---|---|---|
| 1 第一街区 | 12/12 | 12 | 高 |
| 2 老楼道 | 9/12 | 27 | 高 |
| 3 夜市 | 11/12 | 18 | 高 |
| 4 写字楼 23 层 | 12/12 | 16 | 高 |
| 5 城中村 | 11/12 | 23 | 中 |
| 6 城中村地下 | 7/12 | 35 | 中 |
| 7 港口 | 8/12 | 37 | 中 |
| 8 城郊别墅 | 10/12 | 34 | 中 |
| 9 雨夜追捕 | 11/12 | 32 | 中 |
| 10 天网恢恢 | 6/12 | 39 | 低 |

**总胜率 81%，三星率约 43%。**

调平衡时踩过的坑（都有数据支撑）：

0. **押送车发车太频繁导致分数爆炸**
   第一版容量 4、发车 +200，模拟跑出来一局发车 140 次、得分 3 万+。
   原因是连锁每一层都会装车，一次大串联能发好几次车。
   改成容量 5、发车 +120 后回到正常区间。

1. **保护伞「清整列」会自激爆炸**
   清一列带出更多伞 → 更多伞清更多列。实测平均清掉 176 格，而棋盘只有 64 格。
   改成固定半径十字爆裂后，强度可控且可预测。

2. **恶霸「每个扣 1 步」让人莫名掉步**
   长串联里一次掉十几步，玩家完全无法预判。改成只扣分，步数只按操作走。

3. **连锁 4 倍加成让分数爆炸**
   平均得分 6418 但三星线才 1800，三星形同虚设。封顶降到 2.6，并全线重定星级线。

4. **双类型目标的难度是叠加的**
   L2 要 52 个（双类型）才 30 步，而 L1 单类型 30 个就够 —— 目标数量不能按加法算。

## 六、玩法实验室（方向探索）

用户反馈「也许可以不是消消乐」，所以做了一个可玩原型 `/lab`：

**押送车（排序解谜）**
- 3 条车道各停一辆押送车，颜色固定，装 4 人发车
- 点队列里的坏人 → 进同色车道
- 队列前 3 个都塞不进任何车道 → 自动弃人扣分
- 核心策略：**顺序**。抽错顺序会让队列堵死

和三消的本质区别：
- 三消靠运气掉落 + 局部匹配，输了觉得是运气差
- 排序解谜靠全局规划，输了觉得是自己想错了——后者更容易「再玩一局」

**这个原型踩的坑**：初版把死锁检测写在 `useEffect` 里并且会 `setState`，
导致「弃人 → 重渲染 → 再检测 → 再弃人」无限循环，步数瞬间清零。
改成 `useReducer` 后所有状态迁移原子化，问题消失。
